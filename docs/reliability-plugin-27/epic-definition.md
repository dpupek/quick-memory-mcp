# Quick Memory reliability and Codex plugin pilot

[#27](https://github.com/dpupek/quick-memory-mcp/issues/27) gives SysOps operators and Campus developers three ways to use the memory they already keep: resume a case, recover a sourced decision, and save a verified handoff. Existing MCP clients and the Windows-hosted service remain supported throughout the work.

## Success criteria

- A project administrator can demonstrate that the same tier and entry protections apply through HTTP and MCP.
- A service operator can upgrade and roll back on Windows, restore a backup, and recover every acknowledged save after restart.
- A returning user can resolve the right project and find a dated source with a bounded initial response. Existing integrations can still request full records.
- Each pilot cohort has its own baseline, scored results and rollout decision. The [roadmap](roadmap.md) defines the proposed thresholds.

The delivery scope covers one service and a plugin in the private workspace marketplace. A database migration, broad plugin distribution and a new embedding pipeline require separate evidence and decisions.
